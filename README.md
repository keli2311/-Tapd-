﻿ # TAPD 非通过用例批量改为通过
 
 脚本：[tapd_pending_to_pass.user.js](./tapd_pending_to_pass.user.js)。适用于所有 TAPD 测试计划详情页：
 
 https://tapd.tencent.com/*/sparrow/test_plan/detail/*
 
脚本支持两种执行方式：一键执行会使用页面原生“全选当前已加载数据”复选框，然后将全部选中用例 ID 一次提交为 pass；批量执行会每批 10 条将非通过用例改为通过。两种模式都会核对页面实际结果。

## 执行当前页开启计划（2.5.1）

先在第一层测试计划列表页使用网页原有筛选功能，将“状态”筛选为“开启”（URL 参数 data[Filter][status][]=开启）。然后点击右下角的“执行当前页开启计划”。脚本只读取当前页已加载的开启计划，保留当前视图、负责人和其他筛选条件，不翻页、不收集其他页的计划。

队列在当前页签逐个打开计划原生的“规划&执行”链接，自动全选用例，并把所有选中 ID 通过批量执行接口一次提交为 pass；不需要手动切换另外两个页签。每个计划执行前会重新检查其列表状态，并核对已加载用例数等于计划总数；必要时展开目录等待加载。已全部通过的计划不重复提交，空计划单独记录。

执行面板显示当前计划和用例进度，可点击“暂停计划队列”，再回到原列表点击“继续执行剩余计划”。队列通过当前页签的 sessionStorage 跨页面保存；接口回执成功后刷新详情页，只核对已提交用例的实际状态，不重复提交。超过 12 小时的任务需要手动继续。

每个计划最多等待 60 秒加载完整列表、60 秒确认全部通过。接口未确认成功、权限不足、列表加载不完整或结果未确认的计划会记录失败并继续其余计划；已提交的计划不会自动重发。结束后自动返回原列表，展示完成、空计划、失败/待确认和状态改变跳过的数量，以及逐计划结果。

安装更新时请保存整个脚本（本版新增列表页和计划概览页的匹配规则）。然后刷新第一层列表页，再点击新增按钮启动；安装或刷新本身不会启动新队列。
 
 ## 使用方式
 
 1. 在 Edge 或 Chrome 中安装 Tampermonkey 扩展，新建脚本。
 2. 粘贴 tapd_pending_to_pass.user.js 的全部内容并保存。
 3. 打开任意 TAPD 测试计划详情页（/sparrow/test_plan/detail/*）；右下角会显示待处理数量。
4. 点击“一键执行用例”全选已加载的用例并一次性提交 pass，或点击“批量执行用例”按每批 10 条处理非通过用例。
5. 全选范围包含折叠目录下已加载的用例及已经通过的用例，后者也会再次执行；未加载的分页或过滤掉的用例不在范围内。
 
 ## 技术要点
 
 - 识别非通过用例的依据：span[rel] 的 rel 属性值（status_pass / pass 视为通过，其余为非通过）。
- 一键执行：使用原生全选事件并检查每条用例的勾选状态，然后一次调用 execute_result/batch_execute/0/，传入全部选中 ID 和 data[Result][result_status]=pass；缺少权限、全选不完整或列表发生变化时会停止。
- 批量执行：每批最多 10 条非通过用例，直接调用 TAPD 批量执行接口（execute_result/batch_execute/0/）提交 result_status=pass，不勾选、不操作行菜单；成功后主动重绘对应行并等待状态变为"通过"后再处理下一批；失败或超时的批次先跳过，剩余批次完成后再统一进入重试流程。
- 兼容性：@match 覆盖 tapd.tencent.com 和 tapd.woa.com 下的 plan_list、view、detail 三层页面，不限定具体项目 ID 或迭代。
 - 超时处理：一键模式最多等待 30 秒并显示已确认通过的数量；超时后提示检查页面结果或确认框，不自动重复提交。批量模式每批等待最多 12 秒。
 - 保持活跃：执行期间播放人耳几乎听不到的循环音（阻止浏览器高强度节流）并请求屏幕唤醒锁（阻止系统休眠）；暂停或完成后自动释放。
- 失败重试：批量模式有失败用例时 10 秒后自动重试（可点击取消）；连续 3 次仍失败则自动刷新页面并继续批量执行，刷新后仍失败则停止。旧逐条模式的刷新恢复状态会清除。
- 取消执行：一键模式提交前可取消；提交后等待页面结果，不能撤回已提交的请求。
